# A股投资研究知识库

一个以 **Markdown 文件驱动** 的个人 A 股投资研究知识库，用于长期沉淀：

- 市场环境认知
- 行业趋势研究
- 公司价值分析
- 股票状态判断
- 交易决策体系
- 重点股票首次研究
- 重点股票长期研究档案
- 每日市场复盘
- AI 辅助增量更新

当前版本：**v1.0.1**

---

# 一、项目定位

这个项目不是行情软件，也不是自动荐股工具。

它的核心目标是建立一套：

> **可以长期积累、持续验证、不断纠错和逐步完善的个人 A 股投资研究知识库。**

整体研究顺序：

```text
市场环境
↓
行业趋势
↓
公司价值
↓
股票状态
↓
交易决策
```

重点股票则形成另一条完整工作流：

```text
发现新股票
↓
重点股票 AI 研究模板
↓
判断是否值得长期研究
↓
建立独立股票档案
↓
持续跟踪
↓
AI 增量更新
↓
逻辑强化 / 弱化 / 证伪
```

每日复盘负责记录短期变化：

```text
今天发生了什么
↓
什么变了
↓
为什么重要
↓
明天看什么
```

项目始终强调：

> **事实数据、市场预期、投资判断必须分开。**

不简单预测股票涨跌，而是重点研究：

> 为什么值得关注、逻辑是否成立、当前发生了什么、什么情况下原来的判断会失效。

## 1. 全局投资体系

### 01 市场环境分析

主要研究：

- 当前市场阶段
- 流动性
- 市场宽度
- 主线方向
- 市场情绪
- 风险环境
- 每日最小观察指标
- AI 市场环境提问模板

核心问题：

> **现在值不值得承担风险？**

---

### 02 行业趋势分析

主要研究：

- 行业成长空间
- 生命周期
- 景气周期
- 供需关系
- 价格与库存
- 行业增长驱动
- 产业链
- 利润池
- 龙头企业
- 行业领先指标

核心问题：

> **这个行业为什么可能增长，利润最终会落到哪里？**

---

### 03 公司价值分析

主要研究：

- 商业模式
- 核心竞争优势
- 成长能力
- 财务质量
- 估值
- 市场预期
- 股东与资本行为
- 逻辑证伪

核心问题：

> **这家公司为什么能够持续赚钱，这种能力还能持续多久？**

---

### 04 股票状态分析

主要研究：

- 底部震荡
- 启动阶段
- 主升阶段

- 下降阶段
- MA5 / MA10 / MA20 / MA30 / MA60
- 量价关系
- 筹码结构
- MACD / RSI / KDJ
- 支撑、压力与趋势失效条件

核心问题：

> **这只股票现在在哪里、强不强、什么情况下当前趋势判断失效？**

---

### 05 交易决策体系

主要研究：

- 买入逻辑
- 参与条件
- 风险位置
- 盈亏比
- 仓位管理
- 加仓条件
- 持仓检查
- 减仓
- 卖出
- 逻辑证伪
- 交易复盘

核心问题：

> **如果判断正确如何获得收益，如果判断错误如何控制损失？**

# 三、重点股票 AI 研究模板

`stocks/重点股票AI研究模板.md` 用于：

> **第一次系统研究一只新的股票。**

它不是已有股票的日常更新模板，也不是短线买卖模板。

主要解决：

```text
这家公司做什么？
↓
靠什么赚钱？
↓
为什么值得关注？
↓
核心投资逻辑是什么？
↓
竞争优势是否真实？
↓
未来增长来自哪里？
↓
盈利质量怎么样？
↓
市场已经预期了什么？
↓
最大风险是什么？
↓
什么情况下逻辑会被证伪？
↓
是否值得进入长期重点研究池？
```

模板最终将股票分为：

| 评级 | 含义 |
|---|---|
| **A** | 值得进入重点研究池，建立正式股票档案 |
| **B** | 值得继续观察，等待关键变量验证 |
| **C** | 研究价值一般 |
| **D** | 当前不值得继续投入大量研究时间 |

需要注意：

> **A / B / C / D 判断的是研究价值，不是未来涨跌。**

# 七、系统工作原理

系统采用：

```text
data/index.json
↓
生成左侧导航目录
↓
点击文档
↓
JavaScript fetch Markdown
↓
marked.js 转换 Markdown
↓
页面显示
```

因此：

> **Markdown 文件才是真正的数据源。**

HTML 页面中不重复保存文章内容。

这样可以避免：

```text
Markdown 一份
+
JavaScript 又复制一份
```

造成内容不一致。

# 八、使用方法

## 1. 本地运行

由于系统通过 JavaScript `fetch()` 读取：

```text
data/index.json
global/*.md
stocks/*.md
daily/*.md
```

推荐通过本地 HTTP Server 打开，而不是直接双击 `index.html`。

在项目根目录打开 PowerShell：

```powershell
python -m http.server 8000
```

浏览器访问：

```text
http://localhost:8000
```

停止服务：

```text
Ctrl + C
```

- GitHub Pages
- Cloudflare Pages
- 普通网站静态目录
- Nginx / Apache
- SiteGround 等支持静态文件的网站空间

不需要数据库。

- 新客户

- 逻辑证伪

## 应该写入 `daily/`

例如：

- 当日指数表现
- 成交量
- 市场情绪
- 主线板块
- 个股短期趋势
- 均线
- 量价

- 突破或回调
- 当日交易计划

原则：

> **长期档案记录“为什么研究它”。**

> **每日复盘记录“今天发生了什么”。**

# 十一、如何第一次研究新股票

例如准备研究：

```text
600519 贵州茅台
```

推荐流程：

```text
打开：
stocks/重点股票AI研究模板.md
↓
复制其中的AI提问模板
↓
填写股票名称和代码
↓
交给支持联网研究的AI
↓
核验核心数据和来源
↓
判断A / B / C / D
```

如果最终评级为 **A**：

新建：

```text
stocks/600519-贵州茅台.md
```

然后整理成正式长期档案。

如果评级为 B / C / D：

> 不必急于增加到核心股票目录。

这样可以避免：

> `stocks/` 最终变成普通自选股列表。

# 十三、不要每次重新生成整篇股票研究

错误方式：

```text
每季度
↓
重新让AI生成完整研究报告
↓
覆盖旧文件
```

这样很容易失去：

- 历史判断
- 原始投资逻辑
- 判断发生变化的过程
- 当初为什么看对或看错

推荐方式：

> **增量更新。**

例如：

```text
原判断：
新业务仍处于产能爬坡阶段

新季度：
利用率明显提高，扣非利润改善

更新：
强化新业务盈利改善逻辑
```

# 十四、事实、预期、判断必须分开

长期建议保持：

```text
【事实】
已经发生并可以核验

【市场预期】
市场正在交易的未来预期

【投资判断】
基于事实和预期形成的判断

【未核验】
暂时没有可靠来源支持
```

例如：

```text
【事实】
公司1.6T产品已经批量出货。

【市场预期】
市场预计下一年度1.6T继续增长。

【投资判断】
如果放量同时毛利率保持稳定，核心逻辑继续强化。
```

不要把：

> “市场预计会发生”

写成：

> “公司已经实现”。

---

# 十五、新业务成熟度必须严格区分

研究科技成长股时尤其重要。

统一使用：

```text
研发
↓
样品
↓
客户验证
↓
小批量
↓
批量
↓
快速放量
↓
规模盈利
```

不要把：

- 研发 → 商业化
- 送样 → 批量出货
- 规划产能 → 实际产量
- 客户验证 → 已经贡献利润

混为一谈。

# 十六、如何维护全局投资体系

`global/` 属于方法论，不需要频繁更新。

只有下面情况出现时再修改：

- 自己形成新的长期投资认知
- 原有方法发现明显缺陷
- 某些指标长期证明没有实际价值
- 找到更简单、更稳定的判断方式
- 整体研究流程发生明显升级

维护原则：

> **优先修改旧结论，不要只在文档末尾持续追加。**

目标不是让文档越来越长，而是：

> **越来越准确、越来越容易使用。**

# 十七、如何新增股票

## 第一步：创建 Markdown 文件

统一命名：

```text
股票代码-股票名称.md
```

例如：

```text
600519-贵州茅台.md
000858-五粮液.md
002594-比亚迪.md
```

放入：

```text
stocks/
```

---

## 第二步：更新 `data/index.json`

新增股票后，需要加入导航数据。

示例：

```json
{
  "id": "stock-600519",
  "file": "stocks/600519-贵州茅台.md",
  "title": "600519 贵州茅台",
  "icon": "📄",
  "keywords": [
    "贵州茅台",
    "600519",
    "白酒"
  ],
  "updated": "2026-08-06"
}
```

注意：

> 实际字段结构以当前 `data/index.json` 为准，不要随意修改已有数据结构。

# 十九、资料来源维护

重要信息建议按照下面优先级：

```text
交易所公告
↓
公司年报 / 半年报 / 季报
↓
公司投资者关系资料
↓
公司官网
↓
权威行业资料
↓
高可信财经媒体
```

不建议把以下内容直接作为长期核心事实：

- 自媒体文章
- 股吧讨论
- 无来源截图
- 不可追溯的二手数据
- AI自动生成但没有来源的数据

# 二十、AI 的正确使用方式

AI 在这个项目中更适合做：

- 公开资料整理

- 新旧数据比较
- 行业信息整理
- 投资逻辑检查
- 风险查漏
- 证伪检查
- 增量更新建议

推荐流程：

```text
AI找信息
↓
AI结构化
↓
人工核验
↓
自己判断
↓
写入知识库
```

AI 不应该替代：

> **最终投资判断。**

当前正式版本：

```text
v1.0.1
```

## 内容小更新

例如：

- 更新季度数据
- 修正文档
- 新增资料来源
- 新增每日复盘

可以使用：

```text
v1.0.1
v1.0.2
```

## 功能增加

例如：

- 搜索能力明显增强
- 新增标签系统
- 新增新的导航能力

可以使用：

```text
v1.1.0
v1.2.0
```

## 大幅重构

例如：

- 从纯静态系统升级为数据库 WebApp
- 大幅改变内容架构

再考虑：

```text
v2.0.0
```

# 二十三、Git 使用建议

每次 Commit 尽量只解决一个明确主题。

例如：

```text
更新工业富联2026半年报研究
```

或者：

```text
新增贵州茅台长期研究档案
```

或者：

```text
新增2026-08-06每日复盘
```

避免一次 Commit 同时包含：

- 大量内容更新
- 页面重构
- CSS修改
- JavaScript修改
- 多只股票重写

这样以后更容易回溯。

# 二十四、建议重点备份的内容

真正构成长期个人研究资产的是：

```text

```

而长期研究记录一旦丢失：

推荐至少保存：

```text

+

```

有需要时再增加云盘备份。

## 方向七：SQLite / 数据库

当前：

> **不建议升级数据库。**

Markdown 的优势：

- 简单
- 可直接阅读
- 可直接编辑
- 可 Git 管理
- 容易备份
- 容易迁移

- 数百只股票
- 大量结构化数据

等明确需求时，再考虑 SQLite。

> **持续积累高质量内容。**

# 二十七、长期维护原则

建议长期坚持以下原则：

### 1. 内容优先

先把研究做好，再考虑页面。

### 2. 事实优先

事实 > 预期 > 判断。

### 3. 增量更新

不要反复重写完整股票档案。

### 4. 证伪优先

不仅寻找支持自己观点的信息，也主动寻找证明自己错误的信息。

### 5. 简单优先

没有真实需求，不增加复杂功能。

### 6. 长期与短期分离

长期逻辑放 `stocks/`。

短期变化放 `daily/`。

### 7. 重要信息替换旧结论

不要无限追加内容。

### 8. 保留可靠来源

重要数据尽量能够追溯。

# 二十九、项目目标

这个项目最终不是为了保存更多文章。

真正目标是建立：

> **属于自己的长期投资研究操作系统。**

随着时间积累，希望能够越来越清楚地回答：

- 什么样的市场值得承担风险？
- 什么行业值得长期研究？
- 哪些新股票真正值得投入研究时间？
- 什么公司真正拥有竞争优势？
- 什么增长已经兑现？
- 什么仍然只是市场预期？
- 什么风险最容易被忽略？
- 什么情况下原来的投资逻辑应该被证伪？
- 自己最容易重复犯什么错误？

当这些问题越来越清晰时：

> 这个知识库才真正产生长期价值。
