# A股投资研究知识库

一个以 **Markdown 文件驱动** 的个人 A 股投资研究知识库，用于长期沉淀：

- 市场环境认知
- 行业趋势研究
- 公司价值分析
- 股票状态判断
- 交易决策体系
- 重点股票长期研究档案
- 每日复盘记录
- AI 辅助增量研究

当前版本：**v1.0.0**

---

## 一、项目定位

这个项目不是行情软件，也不是自动荐股工具。

它的核心目标是建立一套可以长期积累、反复复盘、持续迭代的个人投资研究系统。

整体研究顺序：

```text
市场环境
↓
行业趋势
↓
公司价值
↓
股票状态
↓
交易决策
```

重点股票则以独立 Markdown 文件长期保存：

```text
为什么关注
↓
核心投资逻辑
↓
经营状态
↓
市场预期
↓
主要风险
↓
逻辑证伪
↓
关键观察点
↓
AI增量更新
```

项目特别强调：

> **事实数据、市场预期、投资判断必须分开。**

不简单预测股票涨跌，而是重点研究：

> 为什么值得关注、逻辑是否成立、当前发生了什么、什么情况下原来的判断会失效。

# 五、系统工作原理

系统采用：

```text
index.json
↓
生成左侧目录
↓
点击文档
↓
JavaScript fetch Markdown
↓
marked.js 转换
↓
页面显示
```

因此：

> **Markdown 文件才是真正的数据源。**

HTML 页面中不重复保存文章内容。

这样可以避免：

```text
Markdown一份
+
JavaScript又复制一份
```

导致内容不一致。

# 六、使用方法

## 方法一：Windows 本地运行

推荐直接运行：

```text
run-preview.bat
```

然后浏览器访问脚本显示的本地地址。

如果脚本默认使用 Python HTTP Server，通常类似：

```text
http://localhost:8000
```

---

## 为什么不要直接双击 index.html

项目通过 JavaScript `fetch()` 读取：

```text
data/index.json
global/*.md
stocks/*.md
daily/*.md
```

部分浏览器在：

```text
file://
```

方式下会限制本地文件读取。

因此直接双击：

```text
index.html
```

可能出现：

- Markdown 无法加载
- index.json 加载失败
- 页面只有结构没有正文

正确方式：

> **通过本地 HTTP Server 访问。**

---

# 七、手动启动本地服务器

如果不使用 `run-preview.bat`，也可以在项目目录打开 PowerShell：

```powershell
python -m http.server 8000
```

然后访问：

```text
http://localhost:8000
```

停止服务器：

```text
Ctrl + C
```

# 十、如何更新全局投资体系

`global/` 文档属于方法论，不应该频繁更新。

建议只有在下面情况时修改：

- 自己真正形成新的投资认知
- 原方法发现明显缺陷
- 某个指标长期证明没有价值
- 出现更简单、更可靠的判断方式
- AI 研究流程发生明显改进

维护原则：

> **优先修改和替换旧结论，不要只在文档末尾不断追加内容。**

长期目标不是：

> 文档越来越长。

而是：

> **文档越来越准确、越来越简单。**

---

# 十一、如何更新重点股票

每只股票文件末尾已经包含专属的：

```text
AI重新研究与更新模板
```

推荐流程：

```text
新财报 / 新公告 / 重大事件
↓
复制股票文件中的AI模板
↓
交给ChatGPT / Grok / DeepSeek等AI
↓
获取增量分析
↓
自己核验重要数据
↓
判断：
强化 / 未变 / 弱化 / 证伪
↓
只修改真正变化的章节
```

---

# 十二、不要每次让 AI 重写整篇股票档案

错误方式：

```text
每季度
↓
重新让AI生成完整研究报告
↓
覆盖旧文件
```

这样很容易失去：

- 历史判断
- 原始投资逻辑
- 判断变化过程
- 当初为什么看错

推荐方式：

> **增量更新。**

例如：

```text
原判断：
SiC仍处于产能爬坡阶段

新季度：
产能利用率明显提高，扣非亏损收窄

更新：
强化SiC盈利改善逻辑
```

这样长期研究才真正有价值。

---

# 十三、事实、预期、判断必须分开

股票研究建议长期保持：

```text
【事实】
……

【市场预期】
……

【我的判断】
……
```

例如：

```text
【事实】
公司1.6T已经批量出货。

【市场预期】
市场预计下一年度1.6T继续高速增长。

【我的判断】
如果1.6T放量同时毛利率稳定，核心逻辑继续强化。
```

不要写成：

> 1.6T未来肯定高速增长。

因为：

> **未来永远是预期，不是事实。**

---

# 十四、资料来源维护

重要数据尽量优先使用：

```text
交易所公告
↓
公司年报 / 半年报 / 季报
↓
公司投资者关系资料
↓
公司官网
↓
权威行业资料
↓
高可信财经媒体
```

不建议把下面内容直接作为核心事实：

- 自媒体
- 股吧
- 未注明来源的截图
- 不可追溯二手数据
- AI自动生成但没有来源的数据

# 十五、研究数据的更新优先级

股票发生新信息时，可以按照：

```text
会不会改变投资逻辑？
↓
会不会改变盈利能力？
↓
会不会改变竞争优势？
↓
会不会改变风险？
↓
会不会改变长期增长？
```

判断是否值得写入股票档案。

如果都不会：

> 不需要更新长期档案。

# 二十一、AI 的正确使用方式

AI 在这个项目中更适合做：

- 资料整理
- 财报摘要
- 行业信息整理
- 新旧数据比较
- 逻辑变化检查
- 风险查漏
- 证伪条件检查

AI 不应该直接替代：

> **最终投资判断。**

推荐流程：

```text
AI找信息
↓
AI结构化
↓
人工核验
↓
自己判断
↓
写入知识库
```

---

# 二十二、使用多个 AI 交叉研究

股票文件中的 AI 模板可以复制给：

- ChatGPT
- Grok
- DeepSeek
- 其他支持联网研究的 AI

如果几个 AI 的结论不同：

> 不要简单选择自己最喜欢的答案。

应该检查：

- 数据来源
- 数据日期
- 事实是否一致
- 是事实冲突还是判断冲突

最终把：

> **能够核验的事实**

留到长期档案中。

# 二十三、Markdown 写作建议

```markdown

### 三级标题

> 核心结论

避免：

- 过度复杂 HTML
- 大量内联样式
- 页面专用标签
- 难以维护的特殊组件

Markdown 越标准：

> 后期越容易迁移到其他系统。

# 二十四、页面样式维护

页面已经完成桌面端和移动端适配。

如果只是更新投资内容：

> **不要修改 HTML / CSS / JS。**

页面文件与研究内容应该分离维护。

推荐：

```text

→
只改 Markdown

目录变化
→
改 index.json

→
才改 HTML / CSS / JS
```

这能够减少无意中破坏页面的风险。

# 三十一、长期维护原则

这个项目以后尽量坚持下面几条原则：

### 1. 内容优先

先把研究做好，再考虑页面。

### 2. 事实优先

事实 > 预期 > 判断。

### 3. 增量更新

不要反复重写整个股票档案。

### 4. 证伪优先

不仅找支持自己观点的信息，也主动找证明自己错误的信息。

### 5. 简单优先

没有真实需求，不增加复杂功能。

### 6. 长期档案与短期行情分离

长期逻辑放 stocks。

短期变化放 daily。

### 7. 重要信息替换旧结论

不要无限追加内容。

### 8. 所有重要数据尽量保留来源

方便未来复核。

# 三十三、项目目标

这个项目最终不是为了保存更多文章。

真正目标是建立：

> **属于自己的投资研究操作系统。**

随着时间积累，希望能够越来越清楚地回答：

- 什么样的市场值得进攻？
- 什么行业值得长期研究？
- 什么公司真正具有竞争优势？
- 什么增长是真实的？
- 什么增长只是市场预期？
- 什么风险最容易被忽略？
- 什么情况下值得参与？
- 什么情况下应该承认判断错误？
- 自己最容易重复犯什么错误？

当这些问题越来越清晰时：

> 这个知识库才真正产生长期价值。
