# A股投资研究知识库

一个以 **Markdown 为核心数据源** 的个人 A 股投资研究知识库，用于长期沉淀市场认知、行业研究、公司逻辑、重点股票档案和每日复盘。

当前版本：**v1.1.0**

> 本项目用于投资研究、学习和历史记录，不构成任何投资建议。

---

## 一、项目目标

项目不是行情软件，也不是自动荐股系统。

核心目标是建立一套可以长期维护的研究框架：

```text
市场环境
↓
行业趋势
↓
公司价值
↓
股票状态
↓
交易决策
```

同时保留两类独立记录：

```text
重点股票长期档案  →  为什么持续研究这家公司
每日市场复盘      →  今天发生了什么、什么变了、下个交易日看什么
```

长期坚持一个原则：

> **事实、市场预期和投资判断必须分开。**

## 二、v1.1.0 核心变化

本版本重点解决“每日维护过于麻烦”和“AI 输出长度不稳定”两个问题。

### 1. 每日复盘改为单 Markdown 维护

旧流程：

```text
新增 daily/YYYY-MM-DD.md
+
手工修改 data/index.json
```

v1.1.0：

```text
只上传 daily/YYYY-MM-DD.md
↓
前端自动读取 GitHub 仓库 daily/ 目录
↓
自动识别 YYYY-MM-DD.md
↓
自动按日期倒序生成“每日复盘”导航
```

因此，**每天正常维护只需要上传 1 个 Markdown 文件**。

### 2. `data/index.json` 不再管理每日日期

`data/index.json` 继续负责：

- 项目版本
- 全局投资体系导航
- 重点股票导航
- 每日复盘模板入口
- GitHub 仓库配置

它不再保存：

```text
2026-08-04
2026-08-05
2026-08-06
……
```

所以新增每日复盘时不需要再修改它。

### 3. 重构每日 AI 提问模板

`daily/每日复盘模板.md` 已改成可直接复制给 ChatGPT、豆包、DeepSeek 等 AI 的提问模板。

主要变化：

- 不需要填写日期变量
- AI 自动判断最近一个已完成收盘的 A 股交易日
- 固定最终 Markdown 输出结构
- 主线只保留 2～3 个重要方向
- 边际变化只保留 1～3 个
- 重点股票只写真正发生重要变化的股票，最多 5 只
- 全文尽量控制在 1500～2200 个中文字
- 禁止把提问模板再次附在日报末尾
- 避免“30秒结论、复盘结论、最终总结”反复重复同一观点

### 4. 清理旧开发残留

- 删除旧备份 `assets/js/app-2026-0806-1800.js`
- 删除程序中不存在的 `run-preview.bat` 提示
- 本地预览统一使用 `python -m http.server 8000`
- 项目版本统一为 `v1.1.0`
- 历史 `2026-08-06.md` 中附带的旧 AI Prompt 已移除，历史研究正文保留

## 四、每天到底需要上传什么？

### 正常情况下：只上传 1 个文件

例如完成 2026-08-13 的复盘后：

```text
daily/2026-08-13.md
```

上传到 GitHub 仓库的 `daily/` 目录即可。

**不需要修改：**

```text
data/index.json
index.html
assets/js/app.js
README.md
```

### 推荐的每日流程

```text
1. 打开 daily/每日复盘模板.md
↓
2. 复制完整模板给支持联网研究的 AI
↓
3. 检查 AI 返回的重要数据、事实和来源
↓
4. 保存为 YYYY-MM-DD.md
↓
5. GitHub → daily/ → Add file → Upload files
↓
6. Commit
↓
7. 页面自动出现新的历史复盘日期
```

文件名必须严格使用：

```text
YYYY-MM-DD.md
```

例如：

```text
2026-08-13.md
2026-08-14.md
2026-08-17.md
```

不要使用：

```text
8月13日.md
20260813.md
2026-8-13.md
每日复盘-2026-08-13.md
```

## 五、每日 AI 模板的使用原则

模板文件：

```text
daily/每日复盘模板.md
```

它现在是 **AI 提问模板**，不是人工填写表格。

正确使用：

```text
复制整个模板
↓
粘贴给 AI
↓
AI 返回最终 Markdown
↓
人工核验
↓
保存为日期文件
```

不要：

- 在模板中每天手工替换大量变量
- 把模板本身复制到每日复盘结果末尾
- 要求 AI 每天重新分析所有重点股票
- 为了文章更长而增加重复章节

### 为什么限制 1500～2200 字？

每日复盘的价值在于记录：

```text
今天发生了什么
什么发生了变化
为什么重要
下个交易日验证什么
```

不是每天生成一篇几千到上万字的市场报告。

历史文件可以保留原来的长格式；从 v1.1.0 开始的新复盘建议统一采用新模板。

## 七、`daily/` 与 `stocks/` 如何区分？

### 写入 `daily/`

适合短期状态变化：

- 当日指数表现
- 成交额
- 市场宽度
- 情绪变化
- 热点主线
- 板块轮动
- 普通资金变化
- 个股短期量价
- 突破或回调
- 下个交易日观察条件

### 更新 `stocks/`

只有出现可能改变长期逻辑的信息时才更新：

- 财报
- 订单
- 新产品正式量产
- 新客户
- 盈利趋势明显变化
- 毛利率或现金流趋势变化
- 重大资本开支
- 控制权或治理风险
- 重大政策影响
- 核心竞争优势强化或弱化
- 原投资逻辑被证伪

一句话区分：

> `stocks/` 记录“为什么长期研究它”；`daily/` 记录“今天发生了什么”。

## 八、第一次研究一只新股票

模板：

```text
stocks/重点股票AI研究模板.md
```

推荐流程：

```text
发现候选股票
↓
使用重点股票 AI 研究模板
↓
核验公司、财务、行业和风险信息
↓
判断是否值得进入长期研究池
↓
值得长期研究
↓
新建 stocks/股票代码-股票名称.md
↓
加入 data/index.json
```

### 新增股票仍需要修改 `data/index.json`

这一点与每日复盘不同。

原因是新增重点股票属于低频操作，而 `index.json` 还承担股票标题、搜索关键词和导航排序等功能。

例如新增：

```text
stocks/600519-贵州茅台.md
```

同时在 `data/index.json` 的 `stocks` 分组增加对应项目即可。

## 九、长期股票档案采用增量更新

不建议每次财报后让 AI 重新生成整篇研究并覆盖旧判断。

推荐：

```text
原投资逻辑
↓
出现新财报 / 新公告 / 新事件
↓
核验新增事实
↓
判断：强化 / 未变 / 弱化 / 待验证 / 证伪
↓
只修改真正变化的章节
```

这样才能保留历史判断过程。

## 十一、前端工作原理

固定内容仍采用：

```text
data/index.json
↓
生成全局体系 / 重点股票 / 模板导航
```

每日复盘采用：

```text
GitHub Repository Contents API
↓
读取 daily/ 目录
↓
筛选 YYYY-MM-DD.md
↓
按日期倒序
↓
生成每日复盘导航
```

点击任意文档后：

```text
Markdown
↓
fetch()
↓
marked.js
↓
HTML 页面显示
```

### GitHub 配置

配置位于：

```text
data/index.json
```

默认：

```json
{
  "github": {
    "owner": "coowinit",
    "repo": "ai-stock-research",
    "branch": "main",
    "dailyPath": "daily"
  }
}
```

日常更新不需要修改它。

只有以下情况才需要调整：

- 仓库改名
- GitHub 用户名改变
- 默认分支改变
- `daily/` 目录改名
- Fork 到其他仓库并作为正式站点使用

> 自动发现功能适用于可公开读取内容的 GitHub 仓库；不要在前端代码中放入私人访问 Token。

## 十二、本地预览

页面使用 `fetch()` 读取 Markdown，因此不要直接双击：

```text
index.html
```

推荐在项目根目录打开 PowerShell：

```powershell
python -m http.server 8000
```

浏览器访问：

```text
http://localhost:8000
```

停止：

```text
Ctrl + C
```

### 注意

“每日复盘”导航来自 GitHub 远程仓库目录。

因此本地刚创建、但还没有上传 GitHub 的新日期 Markdown，不会自动出现在导航中。上传并 Commit 后即可自动出现。

## 十四、常见问题

### 1. 上传了新的日期 Markdown，但导航没有出现

检查：

1. 文件是否放在 `daily/`
2. 文件名是否严格为 `YYYY-MM-DD.md`
3. 是否已经 Commit 到 GitHub
4. `data/index.json` 中 GitHub owner/repo/branch 是否正确
5. 仓库是否允许公开读取
6. 浏览器控制台是否出现 GitHub API `403` 或 `404`

### 2. 为什么不再修改 `data/index.json` 的 daily 列表？

因为日期文件每天都会新增，属于高频数据；让前端自动发现更适合长期维护。

### 3. 为什么新增重点股票还要修改 `index.json`？

因为新增重点股票是低频操作，而且需要维护标题、关键词和导航顺序。没有必要为了少改一次 JSON 而增加更多前端复杂度。

### 4. 本地双击 HTML 为什么打不开 Markdown？

浏览器对 `file://` 下的 `fetch()` 有安全限制。使用本地 HTTP Server 即可。

### 5. GitHub API 暂时失败怎么办？

全局体系、重点股票和每日模板仍由本地 `index.json` 管理，可以继续阅读；自动历史日期列表可能暂时无法加载，稍后刷新即可。

## 十五、维护原则

### 原则 1：先维护内容，不频繁改程序

正常情况下：

```text
每日 → daily/*.md
重大公司变化 → stocks/*.md
投资体系变化 → global/*.md
```

HTML / CSS / JavaScript 只有明确功能问题时才修改。

### 原则 2：信息越重要，来源越要可靠

重要事实优先核验：

```text
交易所 / 公司公告 / 巨潮资讯
↓
公司官网 / 官方机构
↓
高可信行业资料和财经媒体
↓
其他信息源
```

### 原则 3：AI 是研究助手，不是事实来源本身

AI 输出应继续检查：

- 日期
- 数字
- 公告
- 财报
- 政策
- 订单
- 产品进度
- 资料来源

### 原则 4：不为了完整而制造信息

无法核验时：

```text
未核验
```

优于猜测一个看起来精确的数字。

### 原则 5：项目要越来越简单

长期目标不是不断增加模块，而是：

> **更少的维护动作、更稳定的输出、更容易回看历史判断。**
